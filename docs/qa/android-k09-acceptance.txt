K09 — Profile changes and target explanation

Scope and applicable requirements
- Plan §5.8/13, §8.9, §10.1, §17.4/14, §18.2–8, §19.10.
- Edit profile/body/goal/food preferences through shared K07 controls. Specialist
  target and explicit age confirmation are optional; age never advances silently.
- Preview shows changed inputs, before/after values, versions, user reason,
  assessment limitations and a separate future-menu boundary. Cancel writes nothing.
- Confirm atomically appends profile, assessment and future-plan request. Retry is
  idempotent; stale profile rejects; a receipt write failure rolls everything back.
- History displays saved inputs/date/timezone, formula/policy versions where present,
  general/specialist/test-only path and readable reasons. No clinical approval is inferred.
- Currency now survives amount-free profiles; old snapshots decode with a nullable
  currency. Legacy unknown currency must be supplied in the editor, never guessed.
- FuturePlanPreview/Acceptance binds exact plan/profile revisions, freezes past and
  consumed items, and carries before/after aggregates. Actual calculation, display
  of a computed menu delta and atomic application are K16; K09 only queues a request.
