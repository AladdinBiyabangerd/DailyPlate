İCRA QAYDASI
1. Nömrə sırası əsas ardıcıllıqdır; asılılıqlar minimum texniki şərtlərdir.
2. Bir chatdə bir Kxx götür. Böyükdürsə Kxx-a/Kxx-b kimi böl, ilkin qəbul
   ssenarilərini saxla və növbəni yenilə. Növbəti böyük hissəyə keçmə.
3. Əvvəl AGENTS.md, docs/context/current-task.md, .local-ci/README.md,
   .cursor/rules/code-organization.mdc və aid plan bölmələrini oxu.
4. git status/core.hooksPath yoxla; workflow.py start ilə branch aç.
   Yerli workflow feat/fix/chore/refactor/docs prefikslərini tələb edir.
5. Hər hissə işləyən kod, aid testlər və qəbul sübutu ilə bitir. Domain qaydası
   UI və saxlama kodundan ayrı olur; konkret qovluqlar K01-də seçilir.
6. Unit = ayrıca qayda; integration = real lokal DB/API sərhədi; E2E = istifadəçi
   girişi→hərəkət→saxlanmış nəticə→geri/xəta. Öz hesablamamızı mock etmirik;
   fake provider yalnız xarici sərhəddədir. Testin yazılması keçməsi demək deyil.
7. UI işi üçün ui-craft: əvvəl token və aid şəkillər, sonra renderə baxış,
   kontrast ≥4,5, uzun AZ/EN/RU və böyük mətn yoxlaması. Render mümkün olmayıbsa
   vizual qəbul yoxlanmamış yazılır. Android platforma minimumu qorunur; iOS ölçüləri gələcək mərhələnin istinadıdır.
8. Fokuslu commit → workflow.py finish → merged-main CI. Branch-də CI işlətmə.
   Main CI uğursuzdursa fix branch → düzəliş/commit → finish. .local-ci/ və
   .cursor/rules/local-ci.mdc tarixçəyə daxil edilmir; remote/push yoxdur.
9. docs/context/current-task.md: bitmiş ID, commit, testlər, yoxlanmamış şərtlər,
   növbəti dəqiq ID. Plan dəyişəndə təsirlənən tapşırıqları yenidən uzlaşdır.
10. Bu növbə kanonik məhsul qaydalarını dəyişmir. Sınaq datası ilə işləmək
    insan təsdiqini, real qiyməti və ya cihaz sınağını əvəz etmir.
